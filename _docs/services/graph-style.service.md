## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| GraphStyleService | [src/services/graph-style.service.ts](/src/services/graph-style.service.ts) |

This component is responsible for managing and persisting all user-tunable styling configurations for the graph visualization. It encapsulates settings related to node appearance, link aesthetics, layout physics, and label rendering, providing a centralized, reactive source of truth for the graph's visual presentation.

It functions as a core service within the application architecture, acting as a state manager for graph styling. It reads initial configurations from `localStorage`, merges them with hardcoded defaults defined in [src/core/graph.config.ts](/src/core/graph.config.ts), and exposes the current state via an RxJS `Observable` for consumption by other parts of the application, such as the visualization renderer.

## 2. Public API & Interfaces
| Entity | Type | Description |
| :--- | :--- | :--- |
| `GraphStyleConfig` | Interface | Defines the complete structure for all graph styling parameters, including scene, node colors, link widths, and physics settings. |
| `NodeTypeKey` | Type | A union type enumerating all possible node types supported by the graph structure. |
| `LinkTypeKey` | Type | A union type enumerating all possible link relationship types supported by the graph structure. |
| `GraphStyleService` | Class | Manages the lifecycle, loading, updating, and retrieval of the current graph styling configuration. |
| `GraphStyleService.defaults` | Property | Provides a read-only reference to the default configuration object generated by `buildDefaults()`. |
| `GraphStyleService.style$` | Observable | An observable stream emitting the current `GraphStyleConfig` whenever it changes. |
| `GraphStyleService.style` | Property | A getter returning the current, synchronous `GraphStyleConfig` value. |
| `GraphStyleService.update(next: GraphStyleConfig)` | Method | Updates the internal state with a new configuration object, triggering a save to local storage and notifying subscribers. |
| `GraphStyleService.reset()` | Method | Clears the stored configuration from `localStorage` and resets the service to its initial default state. |
| `GraphStyleService.nodeColor(type: NodeTypeKey)` | Method | Retrieves the resolved RGB color object for a specific node type. |
| `GraphStyleService.linkColor(type: LinkTypeKey)` | Method | Retrieves the resolved RGB color object for a specific link type. |
| `GraphStyleService.levelColor(level: number)` | Method | Retrieves the hex color string for a given graph level, falling back to level 10 if the specific level is not configured. |

## 3. Implementation Details & Side Effects
- **Core Logic:** The service initializes by loading configuration from `localStorage` using `load()`, which attempts to merge legacy configurations (v1) into the current structure (v2). It maintains the state via a `BehaviorSubject`. When `update()` is called, it first calls `resolve()` to convert hex color strings in the configuration into resolved RGB objects for efficient use in rendering paths, and then saves the new state to `localStorage`.
- **Side Effects:** The code explicitly interacts with the browser's `localStorage` API for persistence (reading on load, writing on update/reset).
- **Error Handling:** The `load()` and `save()` methods wrap storage operations in `try...catch` blocks to gracefully handle scenarios where `localStorage` might be unavailable or full, ensuring the application does not crash. The `reset()` method also uses a `try...catch` block for storage removal.
